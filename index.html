03False positive handling

Context before
conclusion.

Not every impossible-looking movement event is a cheat. The tolerance model keeps legitimate causes visible, named, and temporary.

01

Sources are explicit. External pushes, pistons, slime, ice, item use slowdown, vehicles, teleports, latency, and low TPS each have a named place in the model.

02

Allowance is bounded. Contributions decay every tick and the total is clamped. A single flag cannot bank unlimited leniency.

03

Applicability matters. Checks can skip themselves when their assumptions do not hold instead of producing misleading evidence.

04Manual punishment

Staff decide.
Snuff never does.

Every punishment here is typed by a staff member and recorded against their name. The only automatic action is the optional warning ladder, which is off by default and can be set to warn without ever banning.

ban / tempban / ipban

Permanent, timed and address based bans, enforced before the player loads a world.

timeout

Temporary kick for a fixed duration.

mute / tempmute

Blocks chat and commands until lifted.

warn

A recorded warning with a mandatory reason.

unban and the rest

Every action has an exact reverse that logs who lifted it.

Caps and protection

maxduration permissions stop junior staff issuing long bans, and staff can be marked unpunishable.

Durations accept m, h and d in any order, so 1h 10s is valid. A reason is required on every punish command. Run /snuff punishments [player] to review what someone is serving, and /snuff settings to change retention, prevention and the ladder.

05Prevention

Flagging is not
prevention.

Detection that only tells you after the fact is a report. This release can act on the packet, before the server acts on it.

01Setback position

Corrects the client to the last accepted position.

02Cancel attack

Drops the attack before the server swings.

03Cancel placement

Drops the block placement before it exists.

04Cancel break

Drops the block break before it resolves.

05Sync position

Resynchronises the client when it drifts from authority.

06Confidence gate

Every action requires accumulated confidence.

Prevention is confidence gated and can be disabled globally without suppressing flagging or evidence. Visual cheats are neutralised at the source: ores are sent as decoy states, entities with no legal line of sight are hidden from the client, and sounds from behind cover have their origin nudged. Snuff never bans, kicks, mutes or freezes anyone by itself. Every punishment is a staff decision.

06Detection coverage

61 checks.
One evidence system.

The current release groups focused checks across movement, combat, world interaction, and packet behavior. Every check is enabled by default. The set was driven by a defensive study of open source cheat clients, and by false positives caught by playing on a real server with real client connections, which is where the HighJump, Timer and Velocity bugs came from.

  • Fly Movement: Flags movement that cannot be explained by the server-side physics model.
  • Speed Movement: Measures movement against attributes, environment, and recovered input candidates.
  • NoFall Movement: Checks whether fall state and impact behavior remain consistent.
  • AirMovement Movement: Evaluates airborne acceleration against the predicted movement state.
  • GroundSpoof Movement: Tests claimed ground state against observed movement and world context.
  • Step Movement: Checks vertical movement against step height and collision context.
  • HighJump Movement: Detects jump displacement beyond the modelled jump behavior.
  • LongJump Movement: Looks for horizontal distance inconsistent with the current movement state.
  • ImpossibleMovement Movement: Catches movement sequences the predictor cannot reconcile.
  • GroundFlag Movement: Detects sustained ground contact claims that contradict the server block view, the signature of air walk and no fall spoofing.
  • PitchLock Movement: Detects pitch pinned to an exact constant, which placement and glide modules use to defeat server heuristics.
  • Drift Movement: Detects a sustained constant per tick offset between prediction and reported position. The discriminator is drift rate, not magnitude, and it no longer depends on another check running first.
  • Velocity Movement: Checks response to server-applied velocity with tolerance for legitimate context.
  • Reach Combat: Validates attack distance against the server resolved hitbox, never the client cursor. Handles survival, creative and vehicle limits.
  • AttackAngle Combat: Casts the attacker&#39;s real look vector against the true vanilla hitbox and cancels hits that only landed on an expanded box. Catches hitbox cheats that reach alone cannot see.
  • AutoClicker Combat: Evaluates attack timing patterns visible in packet behavior.
  • Aim Combat: Checks suspicious rotation behavior around attacks.
  • KillAura Combat: Evaluates attack and target sequences for impossible behavior.
  • ImpossibleAttack Combat: Flags attack sequences that do not fit server-observable state.
  • Critical Combat: Detects forced criticals produced by emitting extra position packets with a vertical lift too small for gravity, immediately before an attack.
  • RotationSnapBack Combat: Detects a large aim rotation immediately before an attack followed by a reverse rotation immediately after, which human input does not produce.
  • InvalidAttackState Combat: Checks whether an attack is valid for the current player state.
  • FastBreak World: Checks block break timing against material and tool context.
  • FastPlace World: Checks block placement timing and interaction state.
  • Scaffold World: Evaluates placement behavior and the movement context around it.
  • MiningBeyondView World: Detects targeting valuable ores in a region the server never sent, which is knowledge the client could not legitimately have.
  • Nuker World: Looks for impossible or excessive block break behavior.
  • BadPackets Packet: Checks malformed or invalid packet state.
  • PacketSpam Packet: Checks packet volume and timing for abusive patterns.
  • ExtraPackets Packet: Detects more than one position packet per server tick. Vanilla sends exactly one, so this catches packet replay generically. Now backed by a real per tick counter.
  • PacketRate Packet: Detects a sustained deviation of the movement packet rate from the server tick rate, gated on low ping.
  • Timer Packet: Evaluates packet timing against server tick behavior.
  • AntiHunger Movement: exhaustion earned from sprinting and jumping compared against the hunger the server observed
  • AirJump Movement: rising while airborne with no block underneath to jump from
  • SprintSneak Movement: sprint state validated against movement direction and speed
  • Strafe Movement: airborne direction changes compared against the vanilla input model
  • Safewalk Movement: repeated dead stops at a block edge without sneaking
  • Phase Movement: the path between two positions swept against the server block view, rejecting movement through solid blocks, which is the NoClip, Phase, VClip and HClip family
  • Jesus Movement: standing on a liquid surface with no valid block beneath, which is the WaterWalk cheat
  • Spider Movement: sustained upward movement against a wall with no climbable block beside it
  • NoSlow Movement: the vanilla movement slowdown enforced while eating, drinking, drawing a bow, blocking with a shield, sneaking or on soul sand
  • InventoryMove Movement: movement at full speed while a container is open, which vanilla does not allow
  • ElytraFly Movement: gliding with no elytra equipped, or gliding faster than a rocket allows
  • Vehicle Movement: boat, minecart and horse movement limited to the vanilla figures, which is the BoatFly hack
  • FastBow Combat: bow released before the vanilla draw time
  • BowAimbot Combat: bow aim correction repeated at a fixed size with no spread
  • ChestStealer Combat: containers emptied on a fixed click interval, or clicked outside the visible range
  • AutoArmor Combat: armour equipped a fixed short time after the player takes damage
  • AutoPot Combat: splash potions thrown at a fixed interval
  • AutoSoup Combat: food and soup eaten at a fixed interval
  • AutoCrystal Combat: end crystals attacked on a fixed reaction time
  • BedAura Combat: beds and respawn anchors attacked on a fixed reaction time
  • FastUse Combat: item use restarted before the vanilla 32 tick duration, so food, drink or a bow draw completes early
  • Hitbox Combat: every attack raytraced against a vanilla sized hitbox, reporting a run of hits that only landed because the client used a larger box
  • TriggerBot Combat: attacks landing an identical short time after the crosshair reaches a target, with no aim movement in between
  • AutoTotem Combat: slot changes landing an identical short time after the player takes damage
  • InstaMine World: several distinct hard blocks finished inside the same instant window
  • AutoFarm World: farming, mining or fishing with no variance in timing or path, which covers the AutoFarm, AutoMine and AutoFish cheats
  • OreRatio World: valuable ore share of the recent mining path compared against ordinary stone
  • LiquidInteract World: block use through liquids or from outside the angle the player is looking from
  • Blink Packet: movement packets held back and then released in a burst, which is the Blink and LagSwitch cheat

10The server-side boundary

Detect what you can
actually observe.

A server cannot see everything happening on a player’s client. Snuff focuses on resulting server-observable behavior, not on pretending the client is transparent.

01 / DIRECT

Packets and state

Movement, attacks, rotations, interactions, timing, and invalid protocol behavior can be evaluated from server inputs.

02 / PARTIAL

Information abuse

Reach, targeting, Scaffold, and hidden information require behavioral evidence and server-side validation.

03 / OUTSIDE VIEW

Purely client-side changes

X-Ray, ESP and tracers cannot be directly seen, so Snuff stops volunteering the information instead: obfuscated ores, hidden entities without line of sight, and fuzzed sound origins. Freecam and fullbright remain genuinely out of reach.

12Honest limitations

What this
cannot do.

An anticheat that claims to detect everything is lying. These are the known blind spots, stated plainly rather than filled with placeholder checks.

NOT DETECTABLEX-Ray, ESP, ore search

Not detectable, but preventable. There is no protocol signal, so instead the server withholds the data: valuable ores are rewritten as decoy blocks in the chunk data actually sent, verified on Paper 1.21.11.

NOT DETECTABLEFullbright and other local rendering

Not detectable and not preventable. Nothing leaves the client, so nothing arrives at the server.

NOT DETECTABLEViaVersion and Geyser movement

Not yet modelled. Bedrock and legacy protocol clients move differently, so both are exempted rather than risk false positives.

NOT DETECTABLECollision and skipped tick prediction

Not yet simulated. Speed related thresholds stay untuned until the predictor models post 1.8.2 skipped ticks and collision resolution.

NOT DETECTABLEStorage ESP

Not implemented. Ore prevention is real and verified on Paper 1.21.11, but the container viewer in the user guide does not exist yet.

NOT DETECTABLEEntity concealment, tracers and sound fuzzing

Written but not visually verified. These need a screen and an ear, not a test assertion.

NOT DETECTABLEAnti-Xray on other server forks

Driven through private Paper fields, so it is confirmed on Paper 1.21.11 build 132 and unknown elsewhere.

What changed in
1.3.5-dev.

FastPlace counted placements per second against a cap, which catches a flood but not a client that places at thirty a second, comfortably under the cap and comfortably faster than the game allows. A new rule times the gap between consecutive placements. Four of them inside the vanilla four tick cooldown are reported and the placement blocked, with the recent gaps in the evidence.

The placement cooldown is now enforced

FastPlace counted placements per second against a cap, which catches a flood but not a client that places at thirty a second, comfortably under the cap and comfortably faster than the game allows. A new rule times the gap between consecutive placements. Four of them inside the vanilla four tick cooldown are reported and the placement blocked, with the recent gaps in the evidence.

A new check for insta mining

FastBreak validates one block at a time against its own hardness. The other half of the source's advice is the rate across several blocks, which was not measured anywhere. A new `instamine` check collects blocks finished within six hundred milliseconds and reports three or more distinct hard ones, averaging under 25 milliseconds each. The same block counted once is a client retrying, and blocks with almost no hardness are excluded, so breaking grass quickly is never reported.

Two checks read the wall clock instead of packet arrival

The cooldown and insta mining rules both compared times taken from the system clock, which is the wrong clock. Packet arrival times are captured at the network edge in nanoseconds and are what the rest of the timing rules use. Using the wall clock also made both rules impossible to test, since a test cannot control what the system clock says. Both now use arrival times.
